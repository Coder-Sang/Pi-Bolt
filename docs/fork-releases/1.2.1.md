# Pi-Bolt 1.2.1 Message ID build 1

Linux x64 Message ID build of `Coder-Sang/Pi-Bolt`, based on upstream Pi-Bolt `bolt-v1.2.1` at
`e1eb3f775369b10bdfc27e503e6d51b0f1039d88`, including Pi `1.5.2`.

- Retains optional RPC `message_id`, independently of command IDs, and version 1 `queue_update.tracking`:
  ordered admission, actual consumption batches and clearing, including initial prompts and continue paths.
- Message IDs and queue tracking stay outside model requests and persisted sessions. A consumption batch records input
  handoff, not completion of an assistant response. Abort retains unconsumed input until explicitly cleared.
- Preserves input correlation through the new prompt preflight path and queued image normalization. Invalid wire IDs are
  rejected without preventing a later idle shutdown.
- Includes upstream 1.2.1 and Pi 1.5.2: shell authentication commands, incremental Anthropic requests, improved Mermaid and
  Markdown rendering, bounded file tools, resumed-session fixes, and update download retries. Prompt cache warming retains
  Pi-Bolt's `streaming` default.
- Pins the signed 1.2.1 runtime by checksum and GitHub build provenance. Its engine stamp is `9606e2f852e92ee9`.
  The fork's download endpoints, Ed25519 release key and Linux x64 with glibc distribution scope remain unchanged.

The tag and executable version are `bolt-v1.2.1` and `1.2.1`. `build 1` is a display label. This is a signed prerelease and
does not replace the stable `latest` release. Install it explicitly with the installer attached to this fork's release:

```sh
PIBOLT_VERSION=bolt-v1.2.1 sh install.sh
```

The beta update channel also selects numeric prereleases. Previous releases and their assets are retained separately.
No npm package is published by this workflow.

Local validation passed the complete source check, p2's separate check, 83 Agent tests, 142 coding-agent regressions,
50 release/installer script tests, and the in-process search regression. All three compiled variants passed the six
Message ID RPC acceptance cases. Node and the native build also accepted an interactive prompt and displayed the
loopback fixture's reply from outside the repository. No real provider or user credential was used; real-provider and
interactive real-model smoke tests have not been performed.
