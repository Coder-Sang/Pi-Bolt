# Pi-Bolt 1.1.1 Message ID build 1

Signed Linux x64 prerelease of `Coder-Sang/Pi-Bolt`, based on upstream Pi-Bolt `bolt-v1.1.1` at
`0c8faeb30b28671c9aac9ed8bdc62b3dda2dd462`, including Pi `1.5.0`.

- Retains the optional RPC `message_id`, independently of command IDs, and the existing version 1 `queue_update.tracking`
  contract: ordered admission, actual consumption batches and clearing, including initial prompts and continue paths.
- Message IDs and queue tracking remain outside model requests and persisted sessions. A consumption batch records input
  handoff, not completion of an assistant response. Abort retains unconsumed input until explicitly cleared.
- Includes upstream 1.1.1 editor and package-update fixes, Pi 1.5.0 schema/model-catalog changes, and the fork-specific
  download endpoints and release public key.
- Ships default, baseline and JIT Linux x64 archives, compile kit and a pinned upstream runtime. The upstream signature and
  provenance are verified with the independent upstream key; fork payload checksums carry both fork signature formats.

The tag and internal version are `bolt-v1.1.1` and `1.1.1`, compatible with existing numeric-version installers and
updaters. `build 1` is a display label. This is a prerelease and does not replace the stable `latest` release. To select it:

```sh
PIBOLT_VERSION=bolt-v1.1.1 sh install.sh
```

Use the installer attached to this release from `Coder-Sang/Pi-Bolt`. It verifies the fork signature before installing.
The beta update channel also selects numeric prereleases. No npm package is published by this release workflow.

Validation uses source regressions and unpacked binaries against an isolated loopback model fixture, covering queue IDs,
duplicate text, clear, abort, legacy clients, extension input transforms and absence of ID leakage. Real-provider and
interactive model validation have not been performed. The GitHub release environment currently has no reviewer or
deployment-branch protection, and the fork production branch has no branch protection or rulesets. Cryptographic
signature, provenance, clean-tree and payload checks remain required.

The previous stable `bolt-v1.0.10` and unsigned test prerelease `bolt-v1.9.0-message` are retained separately.
